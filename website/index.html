为什么是 Citrine

React 的心智模型，Ruby 的表达方式

Hooks 是"函数组件每次重跑、状态无处安放"的补丁。Ruby 的组件是持久对象， 状态天然活在实例里——所以我们用三个宏代替整本 hooks API。

⚡️

赋值即更新

self.count += 1 触发细粒度重渲染。没有 setState，没有依赖数组，没有 stale closure。

🧩

三宏代替 hooks

prop / state / computed 声明于类体，由元编程生成响应式访问器——读代码像读声明。

🎛

块级更新

view 只执行一次；信号变化只重跑订阅它的 block，精确到节点。无虚拟 DOM diff。

📦

四渲染器

DOM / render-to-string / Canvas / Memory 同一套组件代码——渲染器抽象是框架的脊椎。

🔥

热刷新

citrine dev：改 Ruby 即见，编译错误直接浮层显示，修复自动恢复。

🖥

桌面开箱

citrine package 一条命令产出双击即用的 macOS .app（零依赖 WKWebView 壳）。

对比

同一个计数器

左：React（JavaScript）。右：Citrine（Ruby）。感受一下差异。

function Counter() {
  const [count, setCount] = useState(0);
  const double = useMemo(() => count * 2, [count]);

  return (
    <div>
      <p>{count} × 2 = {double}</p>
      <button onClick={() => setCount(count + 1)}>
        ＋1
      </button>
    </div>
  );
}
class Counter < Citrine::Component
  state   :count, default: 0
  computed(:double) { count * 2 }

  def view
    box(direction: :column) do
      label { "#{count} × 2 = #{double}" }
      button(on_click: :increment) { "＋1" }
    end
  end

  def increment
    self.count += 1   # 赋值即更新
  end
end

没有 useState 的解构数组、没有依赖数组写错的隐患、没有闭包陷阱—— count 就是一个属性，读了就响应，写了就更新。

快速开始

三分钟，从零到热刷新

# 1. 安装
$ gem install citrine

# 2. 建一个应用 my_app.rb
require "citrine/browser"

class Hello < Citrine::Component
  state :name, default: ""

  def view
    box(direction: :column, gap: 10) do
      text_input(value: signal(:name),
                 placeholder: "你的名字")
      label { "你好, #{name}!" }
    end
  end
end

Citrine::DomRenderer.mount_at("app", Hello.new)
# 3. 写一个 index.html（一行脚本即可）
<div id="app"></div>
<script src="my_app.js"></script>

# 4. 启动热刷新开发服务器
$ citrine dev .          # http://localhost:4402
[citrine] 变更: my_app.rb → 通知刷新

# 改 Ruby 保存 → 浏览器自动刷新
# 编译错误 → 页面浮层显示，修复即恢复

# 5. 打包成 macOS 桌面应用
$ citrine package my_app
→ build/CitrineMyApp.app ✨
设计立场

黄水晶，信号的源头

石英振荡器让每一块手表准时跳动——水晶，是信号的物理原型；黄水晶（Citrine）是水晶的宝石形态。 Citrine 框架把"信号"作为 UI 的第一公民：状态是信号，派生是信号，渲染是对信号的订阅。

它站在巨人的肩膀上：Opal（Ruby→JS 编译器，我们唯一的运行时依赖）、 React 的组件与分层思想、Solid 的细粒度更新、Shoes 的"小而美"。 愿景、决策与全部踩坑记录都在 GOALS.md 里。
